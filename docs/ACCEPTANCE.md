# 设备验收清单

以下均为待执行的真机用例。记录设备型号、Android/API、固件、U 盘格式、日期和结果；至少覆盖一台 API 23 电视 / 盒子和一台 API 28+ 设备，建议另外覆盖 API 30/33/34。

| 场景 | 操作 | 期望 |
|---|---|---|
| 安装 | 安装 APK、首次打开、授予 / 拒绝权限 | 启动不崩溃；拒绝时本地上传仍可用 |
| 空库 | 无 U 盘无媒体启动 | 提示页、设置入口可用 |
| 图片 | 上传 EXIF 旋转 JPEG、大图、PNG、WebP | 方向正确、不拉伸、内存稳定 |
| 顺序 | 上传 1.jpg / 2.jpg / 10.jpg，重启 | 自然排序，重启保持媒体及设置 |
| 播放 | 设置图片 3 / 60 秒，加入 H.264 视频 | 图片按时切换，视频结束自动下一项 |
| 解码失败 | 上传伪装图片、损坏 MP4、不支持 HEVC | 跳过记录日志；全部失败 30 秒后重试 |
| USB | 多分区 / 多 U 盘、授权目录后插入 | 自动刷新并能播放 |
| 文件夹范围 | 选择本机媒体子目录，另有其他媒体目录；重启后移除 | 只导入所选目录、授权持久、原文件不删除 |
| 触控 | 点屏幕、暂停、继续、上 / 下一项、媒体工作台四个页签 | 触控目标清晰、暂停不自动跳转、设置无需密码 |
| 缓存模式 | 等待导入后拔 U 盘 | 本地副本继续播放 |
| 直接模式 | 清本地副本、关复制、扫盘、播放时拔盘 | 无崩溃，移除外部列表；重插恢复 |
| 慢挂载 | 重启时 U 盘延迟挂载 10–30 秒 | 挂载广播 / 补扫后出现媒体 |
| WiFi | 同网手机扫码、直接打开网页 | 无需密码即可列出、上传、删除 |
| 大文件 | 上传大于 2 GiB 可播放视频，监测内存 | 内存不随文件大小增长；完整提交后播放 |
| 上传中断 | 上传中关闭网页 / 拔网络 / 杀进程再打开 | 半文件不播放，遗留临时文件清理 |
| 存储空间 | 填满磁盘后上传 / 导入 | 提示或日志，不提交半文件 |
| 端口 | 预占 8080；再占后续十个端口 | 换端口并显示实际地址；全部占用提示并重试 |
| 网络切换 | 断网、换 DHCP 地址、WiFi 转有线 | 播放继续；约十秒内上传服务更新地址 |
| 安全 | 缺少请求标记、错误 Host、跨域 Origin、HTML 文件名 | 拒绝跨站和无标记请求；文件名作为纯文本显示 |
| 方向 | 0 / 90 / 180 / 270；每个方向重启 | 播放、提示、设置正确；方向键符合物理方向 |
| 遥控器 | 只用方向 / 确认 / 返回 / 菜单 | 直接进入媒体库并完成全部设置；焦点清晰 |
| 非循环 | 关闭整体循环；另测单视频循环 | 播完显示结束；确认重新播放；视频循环符合设置 |
| 自启 | 手动首次启动后重启，测广播和默认桌面两种 | 记录固件是否限制后台界面；桌面模式稳定进入 |
| 恢复 | 人为触发崩溃、强行停止、重启 | 区分崩溃恢复与强停限制；无无限崩溃循环 |
| 日志 | 扫描错误 / 解码错误后导出到 U 盘 | 导出可读 |

## 长时间运行

连续 24 小时混播图片、大图、长视频，间隔执行上传、删除、插拔、网络断开和设置旋转。每小时记录 `adb shell dumpsys meminfo com.tvcarousel`、当前媒体、服务可用性和 `adb logcat` 的崩溃 / ANR。观察 Java 堆、Native 堆和解码器占用是否持续增长。24 小时后导出日志，再扩大到 168 小时。无崩溃、无 ANR、无持续内存增长、所有媒体仍能切换才记为通过。

不能把桌面 JVM 流测试等同于电视浏览器上传 2 GiB 成功，也不能把 Debug APK 编译通过等同于 API 23 设备验收通过。
